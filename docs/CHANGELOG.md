# Changelog

All notable engineering milestones for **AI Compute Fabric** are documented in
this file.

This project was developed incrementally from a local GPU scheduling prototype
into an AI-aware compute control plane validated on real AWS, Amazon EKS,
Kubernetes, and NVIDIA GPU infrastructure.

The milestone numbers below describe **engineering milestones**. They are not
claims of formal GitHub releases or Git tags.

# Milestone 0.5 — Durable Artifact Lifecycle - 2026-09-08

Milestone 0.5 completed the durable lifecycle for model artifacts generated by
GPU training workloads.

## Artifact Domain and Persistence

### Added

- `ModelArtifact` domain model.
- Artifact repository abstraction.
- PostgreSQL-backed artifact repository.
- `ArtifactService` lifecycle boundary.
- Job-to-artifact relationships.
- Alembic migration for model artifact persistence.
- Artifact metadata storage in PostgreSQL.

Artifact metadata includes information such as:

- artifact identifier
- originating job identifier
- artifact type
- durable storage URI
- base model
- creation timestamp

## Durable Amazon S3 Storage

### Added

- `ArtifactStore` abstraction.
- `S3ArtifactStore` implementation.
- Recursive artifact-directory publication.
- Durable S3 storage URI generation.
- Private Amazon S3 artifact bucket managed through Terraform.
- Amazon S3 public-access blocking.
- Amazon S3 server-side encryption.
- Amazon S3 versioning.

Durable artifact paths follow:

```text
s3://<bucket>/<job_id>/<artifact_id>/
```

## Workload Identity

### Added

- IAM Roles for Service Accounts for artifact-producing workloads.
- Dedicated Kubernetes workload ServiceAccount.
- EKS OIDC-based workload identity.
- IAM-controlled S3 artifact access.

The workload access path is:

```text
Pod
 ↓
ServiceAccount
 ↓
EKS OIDC
 ↓
IAM Role
 ↓
Amazon S3
```

This avoids embedding long-lived AWS credentials inside training containers.

## Artifact API

### Added

```text
POST /artifacts
GET  /artifacts/{artifact_id}
GET  /jobs/{job_id}/artifacts
```

These endpoints expose durable artifact metadata independently from the
ephemeral training workload.

## QLoRA Artifact Publication

### Added

- artifact publication context injected into workloads
- QLoRA artifact publisher
- recursive QLoRA adapter upload
- artifact metadata registration after successful object upload

Publication order:

```text
QLoRA Training
    ↓
Save Adapter
    ↓
Upload to Amazon S3
    ↓
Register Artifact Metadata
    ↓
PostgreSQL
```

## Real Validation

The final QLoRA artifact lifecycle was validated using:

- Amazon EKS
- NVIDIA Tesla T4
- Qwen/Qwen2.5-0.5B-Instruct
- 4-bit QLoRA
- PyTorch + CUDA
- Amazon S3
- IRSA
- PostgreSQL
- Artifact REST API

The final adapter was retained in private Amazon S3 after the expensive EKS
and GPU infrastructure was destroyed.

# Project Evolution

The project evolved through the following engineering path:

```text
Control-Plane Domain
    ↓
Admission / Queue / Scheduling
    ↓
GPU Resource Management
    ↓
Persistence
    ↓
Amazon EKS
    ↓
Real NVIDIA GPU Discovery
    ↓
Kubernetes Execution
    ↓
Runtime Observation
    ↓
Runtime Reconciliation
    ↓
PyTorch Training
    ↓
QLoRA Fine-Tuning
    ↓
vLLM Serving
    ↓
Amazon Bedrock
    ↓
DevOps MCP
    ↓
Durable Model Artifacts
    ↓
Prometheus / Grafana
```

The completed architecture demonstrates an AI compute control plane rather
than a collection of unrelated Kubernetes workloads.

The central architectural principle is:

> **AI Compute Fabric coordinates AI compute; it does not replace the
> infrastructure that executes it.**

Kubernetes, NVIDIA GPUs, PyTorch, vLLM, Amazon Bedrock, Amazon S3, PostgreSQL,
Prometheus, and Grafana remain execution, storage, persistence, and
observability technologies.

AI Compute Fabric provides the control plane that coordinates workload
admission, priority, placement, accelerator allocation, execution, runtime
state, reconciliation, artifacts, managed inference, AI-native operations,
and operational visibility across those technologies.
